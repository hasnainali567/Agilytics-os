> Date: 2026-11-17
> Rule applied: **STOP taking references and features from Agilytics v1.**
> V1 was built for Saylani bootcamps and was a clone of Notion — NOT a
> project-management tool like Jira / ClickUp. V1 is now only proof that
> the team shipped and ran 3 Saylani bootcamps.
> New reference set: **Jira, ClickUp, Linear, Plane + what companies
> actually asked for in pitches (AI, integrations).**
>
> Scope: every feature in the v2 design pack as it stood on 2026-11-17 —
> `ARCHITECTURE.md`, `SYSTEM-DESIGN.md`, `DESIGN-DECISIONS.md`,
> `DECISION-SHEET.md`, `README.md`, `SECURITY.md`, `docs/FRONTEND.md`,
> `docs/INTEGRATIONS.md`, `docs/AI.md`, `docs/WORKFLOWS.md`,
> `docs/REALTIME.md`, and `apps/api/prisma/schema.prisma`.
>
> This file is the evaluation only. It does **not** edit any other design
> doc, does not change code, and does not change the pitch PDF. The
> changes it calls for are to be applied to the design pack + schema
> when Jhon approves them.

## How to read this

- **Origin** — where the feature came from:
  - `v1` = carried over from Agilytics v1 (bootcamp / Notion-shaped).
  - `v1-fixed` = a v1 feature whose v1 _limitation_ was fixed in v2, but
    whose _shape_ is still v1's.
  - `new` = created for v2 (from company asks / PM standard).
  - `PM-standard` = a normal Jira / ClickUp / Linear / Plane feature,
    judged on its own merits, not on v1.
- **Verdict**
  - `KEEP` — survives the fresh test. Build as designed.
  - `REDESIGN` — the need is real, the shape is wrong. Build the
    PM-standard version described in "What changes".
  - `CUT` — remove from v2 entirely. Do not build it.
  - `DEFER` — real PM feature, but not launch. Put it in a named later
    phase, with a trigger for when it returns.
  - `ADD` — missing from v2, must be added (in the Missing section).
- **⚠️ v1-only** = this feature exists only because v1 had it.
- **🟪 Notion-clone** = shaped like a Notion/wiki product, not a PM tool.

## 2. Flags — the specific things Jhon asked for

### 2.1 Features that exist ONLY because v1 had them ⚠️ v1-only

| Feature                                                                                       | Evidence it is v1-only                                                                                                                                        | Verdict                                                  |
| --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| **Doc Hub as a standalone wiki** (Tiptap docs, global docs library)                           | V1 was a Notion clone; the docs module is its shape. Q12 justifies Tiptap as "same as v1". No company asked for a wiki — they asked for Notion _integration_. | REDESIGN (#9) — project docs + Notion embed.             |
| **Weekly reports as slide Decks** (`deck_chat_sessions` in v1, decks built but commented out) | A presentation builder is not a PM feature. It was v1's dead code, and v2's design still carries "presentation-ready" as a deck, not a report.                | REDESIGN (#11) — generated report, cut the deck builder. |
| **Workspace Home as a social feed** (v1 `workspace-overview-service`, Home feed)              | A feed is a Notion/bootcamp shape. A PM home is My Work + Today.                                                                                              | REDESIGN (#12) — Today / My Work first.                  |
| **Teams as bootcamp groups**                                                                  | V1 teams grouped bootcamp students/mentors. No PM meaning survives that shape without a lead + capacity.                                                      | REDESIGN (#2).                                           |
| **"Tiptap because v1 had it"** (Decision Sheet Q12)                                           | The justification itself is the cap.                                                                                                                          | Re-decide on PM merit (#9).                              |

Nothing else in the design pack is v1-only. The audit found no other
feature whose _only_ reason to exist is "v1 had it" — the rest either
survive the PM test or were already new for v2.

### 2.2 Notion-clone shapes 🟪

| Shape                                                       | Where   | Fix                                                            |
| ----------------------------------------------------------- | ------- | -------------------------------------------------------------- |
| Standalone wiki / Doc Hub as a product                      | #9      | Project docs attached to work; Notion via integration.         |
| Home as a feed                                              | #12     | My Work + Today.                                               |
| Documents as the primary object, tickets as an afterthought | #9, #29 | Tickets are the primary object; docs and files attach to them. |

The rest of the design is PM-shaped: boards, sprints, tickets,
status history, reporting, integrations, automations, AI over work
data. The Notion-clone problem is concentrated in Docs + Home, not
spread across the product.

### 2.3 V1 limitations that v2 already fixed — keep the fix, drop the history

- Sprint with no dates/goal → fixed (dates + goal in schema). ✅
- Ticket with no status/priority/estimate/assignee → fixed. ✅
- Status only on TicketInstance, 4 fixed values → replaced by custom
  BoardColumns. ✅
- No status history → added. ✅
- RLS disabled on all tables + cross-workspace IDORs → tenantId + RLS
  from day one. ✅
- No tests, no AI, no integrations → added as first-class modules. ✅

These fixes are correct and stay. What changes is the _story_: the
pitch should justify the rebuild by the security flaws + the data
model (Claude review point 5), not by "no SEO needed" — Next.js can
run as an SPA, so that reason does not hold up.

## 11. Post-evaluation addition — Custom Roles with Custom Permissions (2026-11-17)

Approved by Jhon, and applied to the design pack as locked decision 21. It is **not** a v1 feature and not a v1 cap — it is new, judged against Jira / ClickUp / Linear / Plane, where custom roles and granular permissions are standard for companies. It is the other half of custom workflows: a company that names its own statuses must also be able to name its own roles and decide who may change a workflow.
